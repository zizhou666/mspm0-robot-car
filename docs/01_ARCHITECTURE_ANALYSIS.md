# 四工程架构与外设审计

## 审计口径

审计同时检查了源码、SysConfig 生成文件和实际工程文件。源工程 A/B 的 Keil 工程与 ticlang/gcc 目录并不完全一致，因此本文区分“磁盘上存在”与“实际被工程编译”。没有把未被工程引用的旧 `.o` 或孤立源码当成有效功能。

## 总览

| 工程 | 架构 | 实际调度 | 结论 |
|---|---|---|---|
| A：PID闭环电机 | noRTOS 裸机 | `while(1)` + GPIO 中断；另有定时器源码但工程引用不完整 | 实际只有 A 相边沿累计计数；不存在可直接移植的速度 PID |
| B：42688 | noRTOS 裸机 | 主循环轮询 ICM42688、姿态解算和 OLED | ICM42688、Mahony 和 OLED 是主体；错误路径原先会永久停机 |
| r2 OLED UI 参考 | noRTOS 裸机 | 5 ms 节拍 + 周期任务 | 可参考固定宽度页面、编码器速度和离散 PI 参数 |
| r1 五向键参考 | noRTOS 裸机 | 5 ms 中断扫描 | 引脚定义可用；原消抖/事件逻辑不够可靠，未原样复制 |

所有工程均未使用 RTOS。最终工程也保持 noRTOS，采用“短中断只置位/计数，主循环执行总线和浮点任务”的非阻塞调度。

## 工程 A：PID闭环电机及编码器

### 结构与真实有效性

- `User/main.c` 是 Keil 工程的实际入口。
- `Driver/Timer.c` 含较重的循迹/陀螺逻辑，但没有可靠地进入当前 Keil 构建；现存 `timer.o` 不能证明源码与目标一致。
- `ticlang`、`gcc` 的 ProjectSpec/工程骨架仍引用空模板，不能作为可用 CCS 工程直接合并。
- `TIMA1` 配置为 5 ms，但实际向量/处理函数存在不一致风险；`TIMA0` 的 50 ms `MOTOR_PID` 被配置，却没有完整启动、ISR 和速度闭环调用链。

### 外设资源

| 类型 | 实例/引脚 | 实际用途 |
|---|---|---|
| GPIO 外部中断 | PA17/PA22（左 A/B），PA15/PA16（右 A/B） | 代码只在 A 相上升沿分别执行 `temp_la++`、`temp_ra++`；B 相未判向 |
| PWM | TIMG6：PB6/PB7；TIMG0：PA12/PA13 | 每个电机两路 PWM，周期 3200 |
| Timer | TIMA1 5 ms；TIMA0 50 ms | 配置存在，但构建和 ISR 链不完整 |
| I2C | I2C1：PA3 SDA、PA4 SCL | MPU6050 相关旧逻辑；定时器源码中含阻塞 I2C/浮点运算 |
| 普通 GPIO | PB26 LED | 状态指示 |
| Capture/QEI | 无 | 编码器不是硬件 QEI/捕获 |
| SPI/UART/DMA/SysTick | 无 | 未发现有效配置或调用链 |

### 参数真实性

- 存在 `MOTOR_ENCODER 260`、`MOTOR_WHEEL_D 67`，但未被速度计算使用，单位和计数口径不明确。
- 所谓 PID 部分实际为循迹 PD（`Kp=70, Kd=5`）和陀螺 PD（`Kp=20, Kd=0.5`），不是电机速度 PID；没有 `Ki` 和电机速度反馈闭环。
- 因此最终工程没有把这些值伪装成速度 PID。速度 PI 的参数明确标注来自 r2 参考工程。

## 工程 B：ICM42688

### 结构与真实有效性

- 实际 Keil 构建入口仍为 `User/main.c`，ICM42688 和 Mahony 代码大段嵌入其中。
- `keil/icm42688.c/.h` 是更适合移植的模块化版本，但原 Keil 工程未将其作为主实现编入；最终工程以它为基础整理接口。
- ticlang ProjectSpec 仍引用不存在/空模板文件，不能声称原工程可在 CCS 直接通过。
- 原代码在 ICM 初始化失败时进入永久 `while(1)`；最终工程改成状态降级，不影响 OLED、按键和编码器。

### 外设资源

| 类型 | 实例/引脚 | 实际用途 |
|---|---|---|
| I2C | I2C1：PA3 SDA、PA4 SCL，100 kHz | ICM42688，地址 0x68，WHO_AM_I 期望 0x47 |
| OLED 软件 SPI | PA17 CLK，PB15 MOSI，PB16 RST，PB17 DC，PB20 CS | 与 ICM42688 不共总线 |
| 姿态解算 | 主循环浮点 | ±500 dps、±4 g，约 200 Hz，Mahony `Kp=1.5, Ki=0.020` |
| 生成配置中的旧 PWM/编码器 | TIMG6/TIMG0/TIMA0 和若干 GPIO | 主循环未使用，是模板残留，未迁移 |
| DMA/UART/SysTick/QEI/Capture | 无 | 未发现有效使用 |

原 OLED 驱动有 framebuffer 和分块 `OLED_Process()`，但字符绘制仍会同步刷新局部区间；最终工程移除了绘制函数内部的总线发送，统一由 `OLED_Process()` 分块提交。

最终又从 `C:\Users\gqj28\Desktop\1\project` 的 SPI 版 ICM42688 工程迁入其传感器配置、校准判稳、Mahony 四元数、零姿态和输出低通逻辑，但没有迁入 SPI 引脚或总线层。当前硬件通信为 PA30/PA29 独立软件 I2C（SDA/SCL）；量程为陀螺仪 ±250 dps、加速度计 ±2 g，100 Hz 更新、20 Hz 数字低通，Mahony `Kp=0.5, Ki=0.005`。

## r2 OLED UI 参考工程

- noRTOS；以 5 ms 定时节拍调度。
- 实际首页来自 `competition_app_display_service()`，约 5 Hz，以固定 21 字符行降低残影和闪烁；旧 `ui.c` 的 32 页系统不是本次 UI 主参考。
- 参考工程的 I2C1 使用 PA29/PA30；检查确认最终固件没有实际初始化 MaixCam I2C 后，按用户要求将 PA29 SCL、PA30 SDA 改给 ICM42688 软件 I2C。
- 电机引脚按参考工程照搬为 TIMA0 四通道；第 6 页实测证明安装后的左右归属与参考命名交叉，最终 PA7/PA4 为左 H 桥输入对，PA3/PB14 为右 H 桥输入对。编码器仍按已验证方案二分组为左 PB4/PB5、右 PB6/PB7，PB4/PB6 为 A 相双边沿中断。
- 参考工程原参数为轮半径 2.4 cm、1060 计数/圈；当前实现是 A 相双边沿 x2，实车出现设定距离约走两倍，因此最终标定为 530 计数/圈。其余参考速度闭环参数为目标 80 cm/s、`Kp=8.0, Ki=0.6, Kd=0`、误差限幅 50、积分限幅 600、输出限幅 999。
- 原编码器边沿/方向写法存在计数口径疑点，最终工程改为 A 相双边沿、读取 B 相判向，并明确 CPR 必须按实物重新校准。
- 最终工程还沿用 r2 的高有效电气逻辑启用 PA27 蜂鸣器和 PB26/PB27/PB22 RGB，但没有复制旧任务状态机；运行时由独立的 `drivers/buzzer_rgb.c/.h` 非阻塞接口控制。

## r1 五向键参考工程

- noRTOS；五向键为 PB12/PB8/PB9/PB10/PB11，低电平有效、内部上拉。
- 原逻辑在 5 ms ISR 中扫描，缺少充分稳定状态消抖，且部分事件映射/空按键对象有风险。
- 最终工程沿用五向键引脚和低有效电气定义，并增加 PA18/PB21 独立翻页键；扫描移到主循环，每 10 ms 一次，连续 3 次一致才改变稳定态。PA18/PB21 始终只在按下边沿产生一次翻页事件；五向上/下/左/右另有独立连发事件，按住 500 ms 后每 100 ms 触发一次，并且只由第 3、4 页参数编辑使用。五向中键仍只实现短按和一次性约 1 秒长按保存，不参与连发。

## OLED 与 ICM42688 总线关系

- 工程 B 原始实现（仅作来源审计）：ICM42688 是硬件 I2C，OLED 是 5 线 GPIO 软件 SPI，两者不共用总线。
- 最终实现：ICM42688 在 PA30/PA29 使用独立 GPIO 软件 I2C；OLED 在 PA17/PB15 使用软件 SPI，并独占 PB20 CS；W25Q64 在 PA12/PA13/PA14 使用另一组软件 SPI，PB25 独立片选。三套软件总线互不共线。W25Q64 最后一个 4 KiB 扇区用于带 CRC32 的参数日志。
- PA29/PA30 已分配给 ICM42688，MaixCam 不能再使用这组 I2C 引脚。

## 实时性结论

- 编码器边沿最高优先级，只做 GPIO 读取和 `int32_t` 加减。
- 10 ms 控制定时器 ISR 只增加待处理计数，不做 PI、PWM、I2C 或 OLED。
- ICM42688 的一次有界软件 I2C 读取、Mahony 浮点更新在主循环执行；100 样本校准被拆成每次一组，约 1 秒完成且不阻塞其他任务。
- OLED 只在主循环分块发送；任何 ISR 中都不会刷新 OLED、延时或执行阻塞式总线通信。
- 12 路灰度在 10 ms 控制任务中一次性读取并计算加权误差；PB23 保持为 P8。巡线 PD、丢线恢复和宽线标记逻辑来自 r2 `competition_platform.c`/`competition_app.c`，输出接入当前速度 PID，而不是迁入与 ICM 引脚冲突的旧四路 PWM。
- W25Q64 擦写只由用户长按保存触发；执行前先关闭电机，正常控制周期不访问 Flash。
